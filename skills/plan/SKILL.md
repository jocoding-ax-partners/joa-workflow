# joa:plan

5단계(계약동결·병렬플랜·정합검토)를 담당한다. 이 스킬 자체는 순서만 서술하고, 통과 판정은 전부
`${CLAUDE_PLUGIN_ROOT}/bin/joa.mjs` 가 한다. 스스로 "됐다"고 판단해 게이트를 건너뛰지 않는다.

## 1. 진입 가드

가장 먼저 실행한다:

```bash
node ${CLAUDE_PLUGIN_ROOT}/bin/joa.mjs require plan
```

exit 1 이면 **즉시 멈추고** 스크립트가 출력한 문장을 그대로 사용자에게 전달한다.
스스로 판단해 진행하지 않는다.

## 2. 막 1 — 계약 동결

4단계에서 나온 mock 을 한 곳의 타입 정의로 승격한다. 담을 것: 요청·응답 스키마 ·
**에러 코드 집합** · 상태 머신 · 각 필드의 소유자.

**메인 스레드가 직접 한다. 서브에이전트에 위임하지 않는다** — 계약은 정의상 단일
writer 여야 갈라지지 않는다.

게이트: 프론트가 mock 을 걷고 계약 타입으로 갈아탄 뒤 `pnpm typecheck` exit 0.

## 3. 막 2 — 병렬 상세 플랜

`superpowers:writing-plans` 를 서브에이전트 N개로 병렬 실행한다. 병렬 기준은 주제가
아니라 **쓰기 경로 교집합이 공집합**인지다 — 마이그레이션 번호·라우트 파일·테이블을
먼저 배분해 겹치지 않게 한다. 각 에이전트는 막 1 의 계약 안에서만 설계한다.

## 4. 막 3 — 단일 정합검토

계획 문서 집합을 먼저 동결하고, **에이전트 하나가** 사용자 여정을 처음부터 끝까지
걸으며 검토한다. 병렬 산출물을 병렬로 검토하지 않는다.

```bash
node ${CLAUDE_PLUGIN_ROOT}/bin/joa.mjs freeze            # 계획 동결
node ${CLAUDE_PLUGIN_ROOT}/bin/joa.mjs docs              # 골 문서가 정본 한 벌을 참조하는지
# …단일 에이전트 e2e 정합검토…
node ${CLAUDE_PLUGIN_ROOT}/bin/joa.mjs freeze --check <동결 해시>
```

`docs` 는 **레포에 골 문서가 이미 있을 때만** 의미가 있다(예: 진행 중인 골에 계획을 덧대는
경우). 처음 만드는 기능이면 골 문서는 `joa:loop` 이 만드므로 여기서는 건너뛴다.

찾는 것: 모순 · 떠넘김(둘 다 "상대가 함") · 중복 · 구멍.

## 5. 2라운드 컷

검토는 최대 2라운드다. 남은 의심은 재검토하지 말고 **실패하는 테스트로 바꿔 큐에
넣는다.** 계획을 계획으로 검증하면 어느 문장도 실행되지 않아 수렴하지 않는다.

## 6. 종료 게이트

```bash
node ${CLAUDE_PLUGIN_ROOT}/bin/joa.mjs pass plan "<무엇을 실행해 통과했는지>"
```

**여기서 나온 계획 문서가 다음 루프 큐의 원료다.** `joa:loop` 이 이 문서들에서 항목을 뽑아
`docs/goal/fix_plan.md` 에 `- [ ]` 로 옮긴다 — 그래야 `joa.mjs floor` 가 센다.

다음은 `joa:teach`.
